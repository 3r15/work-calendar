# 스케줄러 도메인 요약

정밀한 정의는 `docs/DESIGN.md`, JSON 형태는 `docs/DATA-SCHEMA.md`, 근거는 `docs/DECISIONS.md` 에 있습니다.
이 문서는 코드를 쓰기 직전에 머릿속에 올려둘 요점만 담습니다.

## 개념 계층

```
근무 달력(WorkCalendar)
 └ 시간대(TimeSlot)        09:00–12:00 (화~금)
    └ 작업 분류(Category)   "평일 오전"     ← 가시성 단위. 배정에 관여하지 않음
       └ 작업 집합(TaskSet) 청소, 배치구역   ← 배정 단위. 커서와 배타 검사가 여기서 작동
          └ 작업(Task)      청소기(2명)
작업자(Worker) ─ 휴무(Absence)
```

- **작업 집합 = 배정 단위.** 라운드 로빈 커서는 집합마다 하나입니다.
- **작업 분류 = 화면 묶음 단위.** 배정 결과를 바꾸지 않습니다.

## 소속 방향 (D-001) — 뒤집지 말 것

작업집합 소속은 **작업이 갖습니다**. `Task.taskSetIds[]` 가 유일한 출처이고 `TaskSet` 은 `id` 와
`displayName` 만 갖습니다. `TaskSet` 에 작업 목록을 넣고 싶어지면 그건 설계 변경입니다.

`cleaning_am` 과 `cleaning_pm` 은 표시명이 둘 다 "청소" 이지만 별개의 집합입니다.
**ID 와 표시명은 항상 분리합니다.**

## 배타 (conflictsWith)

"한 작업자가 같은 시간대에 두 작업을 동시에 맡을 수 없다" 는 뜻입니다.

- 대칭입니다. 로드 시 양방향으로 정규화합니다. 한쪽에만 적혀 있어도 양쪽에 적용됩니다.
- 모든 작업은 **암묵적으로 자기 자신과 배타**입니다. `requiredCount: 2` 는 서로 다른 두 사람에게 갑니다.
- 검사 범위는 기본이 작업집합 내부입니다. `assignment.crossSetConflicts: true` 면 시간대 전체로
  넓어집니다 (D-002). 엔진은 이 범위를 파라미터로 받아야 하며, 두 값 모두 테스트 대상입니다.

## 배정 알고리즘 (작업집합 단위)

```
1. 대상 작업 필터 — taskSetIds 에 T 포함 && weekdays 에 그날 요일 포함 (빈 배열 = 근무일 전체)
2. 가용 작업자 — active && 그날이 근무일 && 그날 휴무 아님
   순서는 workers.json 정의 순서. 정렬 금지 (결정론이 깨진다)
3. 배타 그래프의 연결 요소로 그룹 분해
   필요 인원 합 내림차순 → 같으면 집합 내 첫 작업의 정의 순서
4. 그룹별로, 작업 정의 순서대로, requiredCount 만큼:
     커서 위치부터 한 바퀴 순회하며 첫 적격자 선택
       적격: 이미 그 작업에 배정 안 됨 && 배타 작업에 배정 안 됨
       동점이면 현재 시간대 배정 건수가 적은 사람 우선
     후보가 없으면 미배정 슬롯으로 기록 (예외 금지)
     커서 += 1
5. 커서를 state/rr-cursor.json 에 저장
```

가용 인원이 슬롯보다 많으면 남는 사람은 그냥 남깁니다 (D-004). 커서는 계속 전진하므로 오늘 빠진
사람이 내일 먼저 배정됩니다.

## 기준 시나리오 — 변경 금지

작업자 4명(A B C D), 청소기(2)·밀대(2)·소독(2)·정리(2), 청소기↔밀대 배타

| 순서 | 작업 | 배정 |
|---|---|---|
| 1 | 청소기 | A, B |
| 2 | 밀대 | C, D |
| 3 | 소독 | A, B |
| 4 | 정리 | C, D |

3명(A B C)이면: 청소기 A·B / 밀대 C·**미배정 1** / 소독 A·B / 정리 C·A

이 결과가 바뀌는 변경은 설계 변경입니다. 코드를 고치기 전에 물어보세요.

## 결정론과 스냅샷

1. 그날 최초 조회 시 계산해서 `state/assign-YYYY-MM-DD.json` 에 저장
2. 이후 조회는 스냅샷을 읽기만 함
3. 재계산은 `assign --force` 로만

**조회할 때마다 다시 계산하면 안 됩니다.**

## 휴무

| 상황 | 동작 |
|---|---|
| 사전 휴무 (배정 계산 전) | 가용 인원에서 제외 |
| 당일 급휴 (스냅샷이 이미 있음) | 배정 **유지** + `absentAssignee: true` (D-009) |

급휴 판정: `createdAt` 의 날짜가 `from` 과 같고 그날 스냅샷이 이미 존재.
`absentAssignee` 는 저장 시점이 아니라 **조회 시점에 계산**합니다. 휴무를 취소하면 `false` 로 돌아갑니다.

자동 재배정은 하지 않습니다. 사람이 이미 움직이고 있을 수 있기 때문입니다.

## 엔진 제약

- 엔진은 **파일 IO 를 하지 않습니다.** 입력은 전부 인자로 받습니다.
- 배정 실패에 예외를 던지지 않습니다. 미배정 슬롯으로 기록합니다.
- `Task.priority` 는 로드·저장만 되고 엔진은 읽지 않습니다 (D-010).
- `core/` 에 `<windows.h>` 를 넣지 않습니다.

## 자주 하는 실수

- `TaskSet` 에 작업 목록을 넣기 → D-001 위반
- `available` 을 이름순으로 정렬 → 결정론 파괴
- 배타를 한쪽 방향으로만 검사 → 대칭 정규화를 거치세요
- 미배정을 0명 배정 대신 예외로 처리
- 급휴 시 조용히 재배정 → D-009 위반
