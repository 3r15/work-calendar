# 작업 스케줄러

매일 누가 무슨 일을 할지 자동으로 정해주는 프로그램입니다. 사람과 작업을 한 번 등록해두면, 아침에 명령어 하나로 오늘의 배정표가 나옵니다. 누가 쉬는지만 알려주면 나머지는 알아서 처리합니다.

```
$ sched today
2026-09-04 (금)

09:00–12:00  평일 오전  ◀ 지금
  [청소]
    청소기  김철수  이영희
    밀대    박민수  최지우
    소독    김철수  이영희
    정리    박민수  최지우
  [배치구역]
    A구역  김철수
    B구역  이영희

13:00–18:00  평일 오후
  [청소]
    청소기       김철수  이영희
    밀대         박민수  최지우
    정리         김철수  이영희
    쓰레기 배출  박민수
  [배치구역]
    A구역  박민수
    B구역  최지우
```

> **아직 개발 중입니다.** 배포용 릴리스가 아직 없습니다. 아래 설명은 완성된 프로그램 기준입니다.

---

## 5분 만에 시작하기

1. 릴리스에서 `sched-win-x64.zip` 을 내려받습니다.
2. 원하는 폴더에 압축을 풉니다. 설치 프로그램은 없습니다.
3. 그 폴더에서 명령 프롬프트를 엽니다. 주소창에 `cmd` 를 치고 Enter 를 누르면 열립니다.
4. 이렇게 칩니다.

```
sched today
```

샘플 데이터가 들어 있어서 아무것도 설정하지 않아도 위 화면이 바로 나옵니다. 내용을 바꾸는 건 그다음입니다.

폴더를 통째로 USB 에 넣어 다녀도 되고, 백업은 폴더 하나를 복사하면 끝납니다.

## 개념 이해하기

이 장만 이해하면 나머지는 명령어를 찾아보면 됩니다. 다섯 가지뿐입니다.

### 1. 작업자

일할 사람입니다. 이름만 있으면 됩니다.

```
$ sched worker list
w_kim   김철수  정기휴무 SUN,MON
w_lee   이영희  정기휴무 SUN,MON
w_park  박민수  정기휴무 SUN,MON
w_choi  최지우  정기휴무 SUN,MON

위 순서가 배정이 도는 순서입니다.
```

왼쪽의 `w_kim` 은 프로그램이 사람을 구분하려고 쓰는 이름표입니다. 화면에는 `김철수` 로 나오니 신경 쓰지 않아도 됩니다. 같은 이름이 두 명 있을 때만 이 이름표가 필요합니다.

### 2. 작업

해야 할 일과 필요한 인원입니다. "청소기 돌리기, 2명" 처럼요.

```
$ sched task list
vacuum      청소기       2명  배타 mop
mop         밀대         2명  배타 vacuum
sanitize    소독         2명
tidy        정리         2명
trash       쓰레기 배출  1명
deep_clean  대청소       2명  SAT
zone_a      A구역        1명
zone_b      B구역        1명
```

`배타 mop` 은 "청소기와 밀대는 한 사람이 같이 못 한다" 는 뜻입니다. 이렇게 적어두면 프로그램이 둘을 다른 사람에게 나눠 줍니다.

### 3. 작업 집합 ← 여기가 고비입니다

**"한 묶음으로 놓고 사람들에게 나누는 단위"** 입니다.

청소기, 밀대, 소독, 정리는 함께 나눠 맡는 일들입니다. 4명이 있으면 이 넷을 4명에게 골고루 돌려야 하죠. 그 "골고루 돌리는 한 묶음" 이 작업 집합입니다.

배치구역(A구역, B구역)은 **별도 집합**입니다. 그래서 청소와 따로 계산됩니다. 청소기를 맡은 사람이 A구역도 맡을 수 있는 건 이 때문입니다.

> **그냥 작업 목록이면 안 되나요?**
> 오전 청소와 오후 청소는 하는 일이 조금 다릅니다. 오전에는 소독이 있고 오후에는 쓰레기 배출이 있죠. 그런데 청소기·밀대·정리는 둘 다에 있습니다.
> 작업 집합이 없으면 "청소기" 를 오전용·오후용으로 두 번 등록해야 하고, "청소기는 2명" 이라는 사실이 두 곳에 흩어집니다. 집합을 쓰면 청소기를 한 번만 등록하고 "오전 청소와 오후 청소 둘 다에 속함" 이라고 적으면 됩니다.

### 4. 작업 분류

**화면에서 묶어 보여주기 위한 것일 뿐입니다.** 배정 결과에는 영향을 주지 않습니다.

위 화면의 `[청소]` 와 `[배치구역]` 이 그것입니다. "평일 오전" 이라는 분류가 청소 집합과 배치구역 집합을 묶어서 보여주고 있습니다.

### 5. 시간대

하루를 나누고, 각 조각에 분류를 붙입니다.

```
$ sched slot list
am_weekday  평일 오전  09:00–12:00  TUE,WED,THU,FRI  weekday_am
pm_weekday  평일 오후  13:00–18:00  TUE,WED,THU,FRI  weekday_pm
am_weekend  주말 오전  09:00–12:00  SAT  weekend_am
pm_weekend  주말 오후  13:00–17:00  SAT  weekend_pm
```

이렇게 하면 오전과 오후에 다른 일이 배치됩니다.

### 전체 그림

```
시간대  "평일 오전 09:00–12:00"
 └ 분류   "평일 오전"          ← 화면에서 묶는 단위
    ├ 집합  "청소"             ← 사람들에게 나누는 단위
    │  ├ 작업  청소기 (2명)
    │  ├ 작업  밀대   (2명)
    │  ├ 작업  소독   (2명)
    │  └ 작업  정리   (2명)
    └ 집합  "배치구역"         ← 청소와 따로 계산됨
       ├ 작업  A구역 (1명)
       └ 작업  B구역 (1명)
```

## 처음 설정하기

샘플을 지우고 직접 만들려면 이 순서로 하세요. 아래는 실제로 실행한 화면입니다.

### 1. 작업자 등록

```
$ sched worker add --name "김철수"
작업자를 추가했습니다: 김철수 (w_1)
$ sched worker add --name "이영희"
작업자를 추가했습니다: 이영희 (w_2)
$ sched worker add --name "박민수"
작업자를 추가했습니다: 박민수 (w_3)
```

이름이 한글이라 프로그램이 `w_1` 같은 이름표를 자동으로 붙입니다. 직접 정하려면 `--id w_kim` 을 덧붙이세요.

매주 쉬는 요일이 있으면 이렇게 합니다.

```
$ sched worker off --worker 김철수 --weekly SUN,MON
정기 휴무를 저장했습니다.
```

### 2. 작업 만들기

먼저 집합을 만들고, 그 안에 작업을 넣습니다.

```
$ sched set add --id morning --name "아침청소"
작업집합을 추가했습니다.
$ sched task add --id vacuum --name "청소기" --set morning --count 2
작업을 추가했습니다.
$ sched task add --id mop --name "밀대" --set morning --count 1 --conflicts vacuum
작업을 추가했습니다.
```

`--conflicts vacuum` 이 "청소기와 같이 못 한다" 는 뜻입니다. 한쪽에만 적으면 반대쪽에도 자동으로 적용됩니다.

### 3. 시간대에 배치

분류를 만들어 집합을 묶고, 시간대에 붙입니다.

```
$ sched cat add --id am --name "오전" --set morning
분류를 추가했습니다.
$ sched slot add --id am_slot --name "오전" --start 09:00 --end 12:00 --cat am
시간대를 추가했습니다.
```

### 4. 확인

```
$ sched validate
문제를 찾지 못했습니다.
```

이 말이 나오면 준비가 끝난 것입니다. 바로 써보세요.

```
$ sched today
2026-09-04 (금)

09:00–12:00  오전  ◀ 지금
  [아침청소]
    청소기  김철수  이영희
    밀대    박민수
```

무언가 어긋나 있으면 `validate` 가 무엇이 문제인지, 어떻게 고치는지 알려줍니다. 사람보다 자리가 많으면 이렇게 미리 경고합니다.

```
오류 0건, 경고 1건

[경고] tasks.json — 작업집합 "아침청소"의 배타 그룹 (청소기, 밀대)는 3명이 필요한데 활성 작업자는 1명입니다. 매일 미배정이 생깁니다.
```

경고는 실행을 막지 않습니다. 알고만 있으면 됩니다.

## 매일 쓰는 법

실제로는 이 세 개만 씁니다.

```
sched now                                지금 할 일
sched today                              오늘 전체
sched off add --worker 김철수 --today     김철수가 오늘 쉼
```

`sched now` 는 지금 시간대만 보여줍니다.

```
$ sched now
2026-09-04 (금)

09:00–12:00  평일 오전  ◀ 지금
  [청소]
    청소기  김철수  이영희
    밀대    박민수  최지우
    소독    김철수  이영희
    정리    박민수  최지우
  [배치구역]
    A구역  김철수
    B구역  이영희
```

점심시간처럼 배정된 시간대가 아닐 때는 다음 시간대를 안내합니다. 빈 화면이 나오지는 않습니다.

## 자주 겪는 상황

### 사람이 갑자기 빠졌어요

휴무를 등록하면 됩니다.

```
$ sched off add --worker 최지우 --today --reason "당일 휴무"
휴무를 등록했습니다: 2026-09-04

⚠ 이미 나간 배정 4건이 이 사람에게 있습니다. 자동으로 바꾸지 않았습니다.
  재배정하려면: sched assign --date 2026-09-04 --force
```

화면에는 바로 `(휴무)` 가 붙습니다. 하지만 **배정 자체는 그대로 둡니다.**

```
    밀대    박민수  최지우(휴무)
```

> **왜 자동으로 다시 안 나눠주나요?**
> 다시 나누면 다른 사람의 일도 함께 바뀝니다. 이미 청소기를 들고 움직이기 시작한 사람의 화면이 갑자기 밀대로 바뀌면 곤란하죠. 그래서 사람이 판단하도록 남겨둡니다.

다시 나누길 원하면 이렇게 합니다.

```
$ sched assign --force
2026-09-04 의 기존 배정을 버리고 다시 계산합니다.
이미 자기 일을 시작한 사람의 작업이 바뀔 수 있습니다. 계속할까요? [y/N] y
2026-09-04 배정을 계산해 저장했습니다.

⚠ 인원이 모자라 2자리를 채우지 못했습니다.
```

### 빨간 글씨로 "미배정" 이라고 떠요

사람보다 자리가 많다는 뜻입니다.

```
    밀대    ─ 미배정 ─  박민수
```

프로그램은 억지로 채우지 않습니다. 2명이 필요한 일에 1명만 넣고 나머지를 비워둡니다. 한 사람에게 두 번 시키는 것보다 "여기가 비었다" 고 보여주는 편이 낫기 때문입니다.

할 수 있는 일은 셋입니다. 사람을 더 등록하거나, 필요 인원을 줄이거나(`sched task edit --id mop --count 1`), 그냥 비워두는 것입니다.

### 배정이 매일 똑같아요 / 매일 달라요

프로그램은 명단을 **순서대로 돌립니다**. 어제 마지막으로 배정된 사람 다음부터 오늘이 시작됩니다.

그래서 일이 딱 나누어떨어지면 매일 같아 보이고, 나누어떨어지지 않으면 매일 조금씩 밀립니다. 둘 다 정상입니다.

`sched worker list` 의 순서가 도는 순서입니다. **이 순서를 바꾸면 배정 결과가 바뀝니다.**

### 표가 깨져 보여요

한글이 네모나 물음표로 보이면 콘솔 폰트 문제입니다. 명령 프롬프트 창 제목을 오른쪽 클릭 → 속성 → 글꼴에서 **굴림체** 나 **D2Coding** 같은 한글 글꼴을 고르세요.

프로그램은 한글 너비를 계산해 표를 맞추므로, 글꼴만 맞으면 어긋나지 않습니다.

### 실수로 지웠어요

데이터 파일을 고칠 때마다 바로 전 내용을 `.bak` 으로 남깁니다.

```
data/tasks.json       지금 파일
data/tasks.json.bak   바로 전 파일
```

`.bak` 을 원래 이름으로 바꾸면 되돌아갑니다. 한 세대만 남으니 두 번 고치면 그 전 것은 사라집니다.

### 두 개의 창에서 쓰면요

두 번째 창이 안전하게 멈춥니다.

```
다른 창에서 이 데이터 폴더를 쓰고 있습니다 (프로세스 1234, 2026-09-04T10:17:00+09:00 부터).
그 창의 작업이 끝난 뒤 다시 실행해 주세요.
```

보기만 하는 명령(`now`, `today`, `worker list`)은 막히지 않습니다.

## 명령어 전체 목록

### 매일

| 명령 | 하는 일 |
|---|---|
| `sched now` | 지금 시간대의 작업 |
| `sched today` | 오늘 전체 |
| `sched show --date 2026-09-10` | 다른 날짜 |
| `sched show --slot pm_weekday` | 특정 시간대만 |
| `sched assign [--force]` | 배정 계산. `--force` 는 다시 계산 |

### 휴무

| 명령 | 하는 일 |
|---|---|
| `sched off add --worker 김철수 --today` | 오늘 하루 |
| `sched off add --worker 김철수 --date 2026-09-10` | 특정 날짜 |
| `sched off add --worker 김철수 --from 2026-09-10 --to 2026-09-14` | 기간 |
| `sched off rm --worker 김철수 --today` | 휴무 취소 |
| `sched off list` | 등록된 휴무 |
| `sched worker off --worker 김철수 --weekly SUN,MON` | 매주 반복되는 휴무 |

### 설정

| 명령 | 하는 일 |
|---|---|
| `sched worker add\|list\|rm\|edit` | 작업자 |
| `sched task add\|list\|rm\|edit` | 작업 |
| `sched set add\|list\|rm` | 작업 집합 |
| `sched cat add\|list\|rm` | 작업 분류 |
| `sched slot add\|list\|rm` | 시간대 |
| `sched validate` | 설정이 어긋나지 않았는지 검사 |

### 관리

| 명령 | 하는 일 |
|---|---|
| `sched prune` | 90일 지난 기록을 한 달치씩 합쳐 보관 |
| `sched update check` | 새 버전 확인 |
| `sched update apply` | 새 버전 적용 |

### 어디에나 붙일 수 있는 것

| 옵션 | 하는 일 |
|---|---|
| `--data-dir <경로>` | 다른 데이터 폴더 사용 |
| `--no-color` | 색 끄기 |
| `--json` | 사람이 읽는 표 대신 JSON |
| `--quiet` | 안내 문구 숨기기 |
| `--strict` | 미배정이 있으면 오류로 끝내기 |

## 설정 파일 직접 고치기

여기부터는 몰라도 됩니다. CLI 만으로 전부 됩니다.

데이터는 `data` 폴더 안의 JSON 파일 넷입니다.

| 파일 | 내용 |
|---|---|
| `config.json` | 근무 요일, 시간대, 분류, 업데이트 설정 |
| `workers.json` | 작업자와 정기 휴무 |
| `tasks.json` | 작업 집합과 작업 |
| `absences.json` | 단발성 휴무 |

`state` 폴더에는 프로그램이 만든 기록이 들어갑니다. 날짜별 배정 결과와 순번입니다. **지우면 과거 이력이 사라집니다.**

직접 고쳤다면 반드시 확인하세요.

```
sched validate
```

파일을 저장할 때는 **UTF-8** 로, BOM 없이 저장하세요. 메모장이라면 저장할 때 인코딩을 `UTF-8` 로 고르면 됩니다. 자세한 필드 설명은 `docs/DATA-SCHEMA.md` 에 있습니다.

---

## 업데이트

새 버전이 있는지 확인합니다.

```
sched update check
```

새 버전이 있으면 현재 버전과 새 버전을 알려주고, 없으면 최신이라고 말합니다. 받아서 적용하려면 이렇게 합니다.

```
sched update apply
```

내려받아 **검증한 뒤에만** 교체합니다. 파일이 손상됐거나 검증할 수 없으면 교체하지 않고 멈춥니다.

**`data` 폴더는 건드리지 않습니다.** 업데이트해도 등록해둔 사람과 작업은 그대로입니다.

자동 확인은 하루 한 번입니다. 끄려면 `config.json` 의 `update.enabled` 를 `false` 로 하세요. 그러면 이렇게 나옵니다.

```
$ sched update check
자동 업데이트가 꺼져 있습니다.
켜려면 config.json 의 update.enabled 를 true 로, update.repo 를 "owner/name" 으로 적어 주세요.
```

인터넷이 없어도 프로그램은 정상 실행됩니다. 업데이트 확인에 실패하면 알려주고 넘어갑니다.
